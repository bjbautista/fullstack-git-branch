La idea

¿Qué es una rama?

Una rama es una referencia móvil a un commit: en la práctica, una línea de trabajo independiente. Al crear una rama no duplicas todo el proyecto; Git crea un puntero ligero. Puedes hacer commits allí sin alterar las otras ramas.

La rama actual suele ser main (en proyectos antiguos, quizá master). Para cada nueva función, arreglo o experimento puedes abrir otra.

commit inicial main
actualización del proyecto
nuevo commit
desarrollo de función feature/busqueda
¿Por qué usarlas?

Un espacio seguro para cada cambio

01

Aísla tu trabajo

Prueba una solución o desarrolla una función sin modificar la línea principal del proyecto.

02

Colabora con claridad

Cada persona puede trabajar en su rama y compartir sus cambios para revisión antes de integrarlos.

03

Experimenta y vuelve

Si una idea no funciona, puedes abandonar su rama sin afectar el código que ya estaba estable.

Git en la terminal

Comandos esenciales

Consultar ramas

git branch
git branch --all

Muestra las ramas locales; con --all, también las ramas remotas.

Crear y cambiar de rama

git switch -c feature/busqueda
# En Git antiguo:
git checkout -b feature/busqueda

Crea la rama y cambia a ella. switch es la opción moderna para cambiar de rama.

Cambiar de rama

git switch main
git switch feature/busqueda

Te mueve entre ramas. Guarda o confirma tus cambios antes de cambiar.

Integrar y limpiar

git switch main
git merge feature/busqueda
git branch -d feature/busqueda

Integra la rama en la actual y, si ya se combinó, elimina la rama local.

Importante: git merge combina en la rama en la que estás ahora. Cambia primero a la rama que debe recibir los cambios, normalmente main.
Un ejemplo habitual

De una idea a la rama principal

Parte de una base actualizada

Ve a main y trae lo último del equipo si trabajas con un remoto.

git switch main

Abre una rama descriptiva

Usa un nombre que indique la tarea, por ejemplo, una función o un arreglo.

git switch -c feature/busqueda

Trabaja y guarda avances

Haz cambios pequeños y crea commits con mensajes que expliquen su propósito.

git add .
git commit -m "Agrega búsqueda"

Revisa e integra

Comparte la rama para revisión y, cuando esté lista, combínala con la rama principal.

git switch main
git merge feature/busqueda
Cuando dos cambios se cruzan

¿Qué pasa con los conflictos?

Puede haber un conflicto si Git no puede decidir automáticamente cómo combinar cambios hechos en la misma parte de un archivo. No significa que el repositorio esté roto: significa que hace falta una decisión humana.

Abre los archivos marcados, conserva o combina el contenido correcto, elimina los marcadores <<<<<<<, ======= y >>>>>>>, y después guarda y confirma la resolución. 

git status
# Edita los archivos en conflicto
git add archivo-resuelto
git commit
Buenas prácticas

Ramas fáciles de mantener

  • Actualiza la rama base antes de empezar.
  • Usa nombres cortos y descriptivos: fix/login.
  • Mantén cada rama enfocada en una tarea.
  • Haz commits pequeños con mensajes claros.
  • Integra y comparte el trabajo con frecuencia.
  • Elimina ramas terminadas cuando ya no las necesites.
Una rama no es una copia del proyecto: es una forma ligera de organizar líneas de trabajo en Git.
